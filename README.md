# Huffman-coding
C语言实现哈夫曼编码：文本压缩

它通过构建一棵哈夫曼树来实现这一目标，整棵树生成的都是前缀码——即任何一个字符的编码，都不会是另一个字符编码的前缀，从而保证解码时不会出现歧义。

## 一、原理
- 核心思想：出现频率越高的字符，分配越短的二进制编码；频率越低的字符，分配越长的编码。这样就能使整体编码后的总长度最小。
- 概念：把每个符号看作叶子结点，权重为该符号出现的频率或概率。通过贪心地反复把权重最小的两个结点合并为新结点，构建一棵二叉树；符号的编码就是从根到叶子的路径（左/右映射为 0/1）。
- 前缀码：生成的码具有前缀性质（没有一个码是另一个码的前缀），因此可唯一解码且无需分隔符。


## 二、构建步骤

假设要对字符串 “aabbbccccddddd” 中各字符进行编码。

1. 统计各字符的出现频率

- a：2次

- b：3次

- c：4次

- d：5次

- 总次数：14

2. 构建哈夫曼树

把每个字符看作一个节点，并以频率作为其权值，放入一个最小优先队列（每次都能取出权值最小的两个节点）。

重复以下过程，直到队列中只剩一个节点（即为根节点）：

- 取出权值最小的两个节点，将它们作为左、右子节点。

- 创建一个新节点，权值为两个子节点权值之和。

- 将新节点放回队列。

具体合并过程：

- 取出最小的 a(2) 和 b(3)，合并为节点 N1，权值 = 2+3 = 5。

- 当前节点：c(4), d(5), N1(5) —— 取出最小的 c(4) 和 d(5)，合并为 N2，权值 = 9。

- 当前节点：N1(5), N2(9) —— 取出 N1(5) 和 N2(9)，合并为根节点，权值 = 14。

最终树的形态：

```
        (14)
       /    \
     (5)    (9)
     /  \   /  \
  a(2)b(3) c(4) d(5)
```

3. 分配编码

从根节点开始，习惯上规定向左为 0，向右为 1（反过来也可以，但需统一）。从根到每个字符叶子的路径，就是该字符的哈夫曼编码。

- a：左左 → 00

- b：左右 → 01

- c：右左 → 10

- d：右右 → 11

4. 编码结果

原字符串 aabbbccccddddd 如果直接用定长编码（4种字符需要2位），14个字符需 14×2 = 28 bit。
使用哈夫曼编码：

- a(2次) → 00，共 4 bit

- b(3次) → 01，共 6 bit

- c(4次) → 10，共 8 bit

- d(5次) → 11，共 10 bit
总长度 = 4+6+8+10 = 28 bit，在这个频率分布下与定长相同。这是因为这里频率差别不大，如果频率相差悬殊（比如有的字符出现几百次，有的只出现几次），哈夫曼编码的总比特数会远小于定长编码。

解码过程：从编码串开头按位顺着哈夫曼树从根往下走，走到叶子就得到一个字符，然后回到根继续，利用前缀码特性可毫无歧义地解码。


## 三、常见应用场景
哈夫曼编码几乎是所有现代压缩技术的“标配”组件，通常与其他算法结合使用。

1. 文件压缩

- ZIP、GZIP 等压缩格式的核心算法 Deflate，就是先用 LZ77 算法消除重复，再对结果进行哈夫曼编码。

- 7z、RAR 等现代压缩软件也都包含哈夫曼编码模块。

2. 图像压缩

- JPEG 对量化后的 DCT 系数进行游程编码后，再用哈夫曼编码进一步压缩。

- PNG 会使用 Deflate 压缩，其中也包含哈夫曼编码。

3. 视频与音频压缩

- MPEG-1/2/4、H.264 等视频编码标准，对变换系数、运动向量等数据做熵编码时，会使用哈夫曼编码（或其变种如 Context-Adaptive VLC）。

- MP3 音频编码中，对量化后的频域数据也采用哈夫曼编码来减少体积。

4. 通信与传真

- 老的 传真机标准（G3、G4） 使用改进的哈夫曼编码（MH、MR、MMR）压缩黑白图像数据。

- 在一些带宽有限或存储空间珍贵的嵌入式通信协议中，也可用哈夫曼编码压缩控制信息或文本。

5. 文件系统与数据库

- 某些数据库或键值存储引擎在存储数据页时，会使用哈夫曼编码等轻量级压缩来节省磁盘 I/O 和空间。

6. 文本压缩预处理

- 纯粹的大文本压缩（如英文小说）可以先做单词/字符频率统计，然后用哈夫曼编码生成紧凑的二进制表示。
